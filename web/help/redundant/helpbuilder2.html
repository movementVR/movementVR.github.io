MovementVR Builder
Overview

Overview

The MovementVR Builder is the graphical interface for designing your VR motor learning experiment. You can customize most aspects of the task:

• Lifting task parameters: the hands’ home position and conditions to start the trial, the plate’s starting position, the target position and success/failure criteria, workspace boundaries…

• Motor learning features: magnitude and schedule of the gain perturbation for adaptation, and feedback visuals, sounds, and effects for reinforcement learning.

• Game objects properties: Customize appearance and physics properties (size, color, animations, friction…) of bird, plate, target, and other game elements.

• Hand Tracking & Data Recording: select unimanual or bimanual task, choose which kinematics to record…

You can choose whether each parameter is constant or if it varies across trials and phases in the experiment. Both options can be designed using our GUIs or by uploading values from a .csv file.

Getting started

Getting started

To begin designing your experiment, click on the Builder tab in the top navigation menu. This will open the Main Builder Interface, your central workspace for defining the parameters of your MovementVR task.

The Main Builder Interface displays a grid of interactive elements — including game objects, task components, trial phases, and quick access buttons — each of which leads to specific configuration options.

You can click on any element or button in the Main Builder grid to edit its associated parameters. This opens a Static Builder window — your first point of contact for configuring both constant and trial-varying parameters.

For constant parameters, this window provides a straightforward form-like interface where you can directly enter or select values.

For trial-varying parameters, each parameter group includes a gear icon next to its label. Click the gear to indicate that the parameter should vary across trials. You’ll then be prompted to choose how to define those values:

• Load from a .csv file, or

• Generate using the Trial Builder interface.

Based on your selection, the appropriate interface will open — allowing you to define how the parameter changes across trials and phases in your experiment. These options are described in more detail in subsequent sections.

Main Builder page

Main Builder page

The interface for the Main Builder page is organized as a grid, where:

• Each row corresponds to a different game object or task component.

• Each column represents a sequential “phase” within a trial.

• Each cell in the grid indicates whether a given object is present or active during a specific trial phase. Colored horizontal bars span across the relevant phases for each object.

Game Objects and Task Components (Rows)

Game Objects and Task Components (Rows)

The left side of the grid lists the main elements involved in the task:

• Reinforcement – Objects and effects that deliver success or failure feedback.

• Bird – A virtual, animated bird that is perched on the target.

• Target – The goal object to reach; includes both functional and visual targets.

• Plate – The object participants lift as part of the motor task.

• Hand Home – The home position for the participant’s hand(s) and criteria to start the trial

• Hands & Perturbation – Hand tracking and recording, and adaptation perturbation

• Workspace – Defines spatial boundaries for valid plate movement.

Clicking on a row lets you edit the properties associated with that game object or task component.

Trial Phases (Columns)

Trial Phases (Columns)

The top of the grid shows the Trial Sequence, with columns representing distinct phases that occur in order during each trial:

1. Intertrial – Pause between trials (also called the intertrial interval).

2. Home Position – Participant returns hands to the designated start position.

3. Plate Contact – Plate appears; system waits for participant to contact it.

4. Plate Lift – Participant lifts the plate toward the target.

5. Feedback – Visual or auditory feedback is given after lift completion.

6. Break – Optional rest phase shown on selected trials.

Click on the “Edit Transitions” button to configure when and how phases change during a trial (e.g., timing, success/failure conditions, etc.). Click on the “Edit Instructions” button to customize participant messages shown during phases.

Setting constant parameters using the Static Builder

Setting constant parameters using the Static Builder

Constant parameters can be set using the Static Builder GUI - a form-like interface with input fields, where you can directly type or click-to-select the desired value for each parameter. To locate a parameter, simply click on the relevant game object or task component on the Main Builder page to open the relevant Static Builder window. Here, parameters are further organized into tabs, and inline info icons explain each parameter in detail (including how to define its value correctly). Click here to open the Static Builder Guide.
