Documentation: setupScript.cs

1. Overview

setupScript is the “experiment stage-hand” for your MovementVR lifting task.
It reads every global setting from CSV and WAV files, then builds and refreshes the scene at the start of the study and on every trial—positioning objects, sizing colliders, wiring trigger volumes, colouring meshes, configuring physics, loading sounds, and deciding which pieces must update from trial to trial.

2. Functional Blocks

Main Responsibilities

  • Configure starting positions for hands and plate
  • Initialize plate, grape, and target properties
  • Manage workspace and game boundaries
  • Configure triggers for gain updates and trial progression
  • Set up and update messages shown during the experiment
  • Set up visuals and colliders for all bounds and game elements
  • Store experiment-wide parameters

Inputs from File

These fields define the configurable experiment parameters, including spatial bounds, shapes, materials, visual settings, and message behavior.

  • Plate/Grape/Target: position, size, mass, drag, colliders
  • Workspace and Boundaries: shape (cube/sphere), sizes, and auto-alignment options
  • Hand starting bounds: "inside" and "outside" bounds, shape and trigger settings
  • Gain reset bounds: conditions for adaptation update trigger
  • Target mesh and success region: size/position/shape + automated options
  • Target birds: species-specific scale and position
  • Trial messages: per-state font, position, color, type, and rotation
  • Audio: success/fail bird sounds and background levels

Startup & configuration loading

StepWhat happensKey methods
startup() – Caches a reference to the sibling plateAndGrapeScript.
– Calls loadFiles().
– Enables the component so updateObjectProperties can be invoked later.		 startup
loadFiles() 1. Downloads successSound.wav and failSound.wav from the headset’s persistent-data folder.
2. Parses three CSV files in the same folder:
  • default.csv – engine-wide defaults.
  • parameters.csv – the constant options you picked in the Builder.
  • trials.csv – per-trial values.
3. For every row it looks up the target script (setupScript, plateAndGrapeScript, etc.) via reflection and pushes the value(s) in with setOptions or setTrials.
4. While reading trials.csv it calls setTrialFlags() so only the objects that actually change from trial to trial are refreshed later.		 loadFiles, setTrialFlags

Per-trial scene construction

  1. Sets the plate
    Places it relative to the participant’s initial HMD position; scales/colours the stand; stores the initial transform for later physics resets.
  2. Configures global boundaries
    Builds the game-area box, task workspace (cube or sphere), and several trigger volumes that watch hand position for hand-start and gain-reset; registers these with handsAndSaveScript.
  3. Draws helper meshes that visualise hand-start regions with auto-size/auto-position logic.
  4. Applies physics settings (mass, drag, angular drag, dynamic & static friction with automatic PhysicMaterialCombine).
  5. Positions grape, target, perch & bird
    Computes automatic Y-offsets, builds a combined “plate + grape” mesh on first setup, adjusts mesh scale via five auto modes, resizes & orients the animated bird.
  6. Manages on-screen text & backgrounds
    Repositions every message prefab (trial number, start, end, success/fail 1-5, origin, lift, contact, break, base), sets font sizes, colours, offsets, rotations, and toggles between rectangle and cartoon backdrops.

Utility logic

  • setOutsideOfBound() — builds the “inside-of” / “outside-of” collider hierarchy for any hand region, respecting shape, direction, and “match all / any” rules.
  • setTrialFlags() — uses regex to decide which broad category a trial variable belongs to (plate, grape, target, friction, messages, bounds) so unnecessary work is skipped.
  • Public getters — getTargetBirdPosition() & getTargetBirdRotation() let other scripts spawn the animated bird at the correct spot every frame.

External dependencies & scene expectations

  • Hierarchy — assumes children such as PlateAndGrape/Plate, Triggers/HandStartingPosition/LeftInsideOf, etc.
  • Sibling scripts — relies on plateAndGrapeScript, targetScript, and handsAndSaveScript for physics resets, target state, and hand tracking.
  • CSV schema — expects rows formatted as script, variable, value1…n, exactly as exported by the Builder / Trial-Builder.

In one sentence

setupScript is the central, data-driven configurator that reads your experiment definition from disk, converts it into concrete Unity objects, and keeps them in sync from trial to trial—so you can prototype complex lifting tasks without touching code again.

Summary of Parameters/Resources handled by setupScript

Plate and Grape

  • platePositionX/Y/Z – Initial position of the plate relative to the headset
  • plateSizeX/Y/Z, plateMass, plateDrag, plateAngularDrag – Plate physical properties
  • grapeLocalPositionX/Y/Z – Position of grape on plate (Y can be auto)
  • grapeSizeX/Y/Z, grapeMass, grapeDrag, grapeAngularDrag – Grape physical properties
  • frictionPlateHandsStatic/Dynamic, frictionPlateGrapeStatic/Dynamic – Friction parameters

Task Workspace & Game Bounds

  • taskWorkspaceBoundShape – Cube or Sphere
  • taskWorkspaceBoundSizeX/Y/Z or Radius – Size of workspace
  • gameBoundLocalPosition{Left, Right, Top, Bottom, Front, Back} – World bounds
  • gameBoundBottomIsGround – Treat bottom as ground (fail if touched)

Hand Starting and Gain Reset Bounds

  • Separate "inside" and "outside" bounds for each hand and each function (start, reset)
  • {lefthand|righthand}Starting[In|Out]Bound* – Positional constraints
  • handGainResetBoundMatchHandStartingFlag – Use same bounds for gain reset and start

Target and Mesh Display

  • targetLocalPositionX/Y/Z – Position relative to plate
  • targetSizeX/Y/Z – Functional success region
  • targetMeshPositionOffsetX/Y/Z – Visual offset
  • targetMeshSizeX/Y/Z – Manually set mesh size
  • targetMeshSizeAuto – Options: none, plate, platePlusTarget, etc.
  • targetMeshShape – Options: Cube, Capsule, Plate, etc.

Target Bird and Perch

  • targetPerchPositionOffset*, Size* – Controls perch geometry
  • tgtBirdsScaleX/Y/Z – Global bird scale
  • Individual size settings for each bird species (e.g., tgtBirdRobinSize*)
  • tgtBirdPositionOffset*, tgtBirdRotation*
  • tgtBirdPositionOffsetYStandOnTargetFlag – Whether bird appears standing on the mesh

Trial Messages

  • For each message type (start, success, fail1–5, origin, base, contact, lift, break):
  • Text position/size/rotation, background color/type, text color
  • e.g., startMessagePositionX/Y/Z, startMessageType, startMessageFontSize...

Audio Settings

  • successSound, failSound – Custom audio clips from persistentDataPath
  • targetBirdVolume, backgroundBirdChirpVolume, backgroundBirdFlyawayVolume

Summary of the Functionalities handled by setupScript

Initialization Functions

  • Start(): Empty default Start; setup happens in startup().
  • startup(): Loads files and enables script logic>.

Configuration from Files

  • Parameters: Loads parameter values for the experiment. For rows with more than 3 columns, it loads trial-by-trial parameter variations and flags which components (plate, target, etc.) need updates per trial. The expected filename is parameters.csv in the persistent data path (internal memory).
  • Audio Setup: Loads audio files for success and failure feedback. The expected filenames are successSound.wav and failSound.wav in the persistent data path (internal memory).

Object Update Flags

Function setTrialFlags marks which game objects (e.g., plate, grape, friction, messages, bounds) need updating based on variables found in the trial csv. These flags optimize per-trial update performance.

updateObjectProperties()

This is the main method that applies configuration during initialization and optionally each trial. It sets transforms, physics materials, visuals, and links collider-trigger logic.

  • initialSetup: called once at startup - sets up most things
  • delayedSetup: called after calibration - sets up variable that depend on the "initial headset position" recorded in calibration
  • Object Update Flags: determines which update blocks will run on every trial, updating objects and variables that depend on parameters that change trial-by-trial

Visual and Message Handling

The script configures a number of on-screen messages displayed during different trial stages: start, end, success, fail1-fail5, break, base, lift, contact, etc.

  • Each has font size, color, background color, position, offset, rotation, and type (cartoon, rectangle)
  • Text uses TextMeshPro
  • Colors and positions are defined relative to headset origin

Hand Bounds & Gain Triggers

Configures the collider volumes for hand position triggers, both for showing the plate and resetting gain. These include both inside-of and outside-of bounds, and can auto-align to plate or be manually specified.

Target Configuration

Target and perch configuration includes collider size, mesh shape/size, perch position, and visual mesh logic. Target mesh size can be computed dynamically (e.g., platePlusTarget) or entered manually.

Bird Configuration

Applies scale and position to each individual bird prefab used in the experiment.

Friction Settings

Applies friction coefficients (static/dynamic) for plate–hand and plate–grape contact, including physics material behavior.

Workspace Boundaries

The setOutsideOfBound method configures inside/outside triggers for hand positioning or gain reset. It adjusts colliders dynamically based on shape (cube/sphere), position, direction, and trial flags.

Public Query Methods

  • getTargetBirdPosition – Returns the 3D position for the target bird.
  • getTargetBirdRotation – Returns the target bird's orientation as a quaternion.
