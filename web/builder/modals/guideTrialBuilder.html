1. Overview  

Trial Builder

The Trial Builder allows you to design experiments with parameter values that change across trials. Unlike the Static Builder — which sets a single, constant value for parameters — the Trial Builder provides tools to create trial-by-trial sequences of parameter values.

Before we start: Select "Trial Builder" as the Input Source

To open and use the Trial Builder, you must select Trial Builder as the Input Source for the parameter group you are configuring.

When you click the ⚙ icon next to a parameter group in the Static Builder, a popup will prompt you to select an Input Source. The "Input Source" tells the builder which interface or file it should use when generating parameter values for your experiment.

MovementVR provides three main Input Source options:

  • Static Builder: A form-like interface that allows you to set a single value per parameter. Use this for parameters that remain constant across all trials (standard perturbation schedules can also be set here). (Default option)
  • Trial Builder: A list-like interface that provides tools to generate sequences of values for each parameter. Use this for parameter values that change across trials.
  • File (CSV): Import parameter values across trials from a CSV file. Use this if you prefer coding over the UI or want to reuse previously generated values (see the SAVE/LOAD guide for details).

Warning: Selecting an Input Source will disables all other input sources and ignore or discard any data they contain (see the SAVE / LOAD guide for details).

Configuring your experiment with the Trial Builder

In the Trial Builder, you will generate a trial-by-trial sequence of parameter values, for the parameters selected via the ⚙ icon (in contrast to the Static Builder, the Trial Builder focuses on a single group of parameters).

The Trial Builder window consists of two main panels, and configuring an experiment involves four main steps divided between these panels:

Left Panel: Manage the list of phases and assign trial types.
  1. Subdivide trials into phases: Organize your experiment into consecutive blocks of trials, called phases.
  2. Assign a trial type to each phase: Each phase is associated with a trial type that defines how parameters behave during that phase. Multiple phases can share the same trial type if they require identical behavior.
Right Panel: Configure trial type settings and parameter value generation.
  1. Define how parameter values behave in each trial type: Specify the method used to generate parameter values—whether they follow a fixed sequence, are randomized, ramp up/down, or adhere to a statistical distribution (this is called the sequence type).
  2. Provide the necessary input values: Enter specific values to control the sequence, such as the list of parameter values, start and end points for ramps, or parameters for statistical distributions.
Example

For instance, we may use the Trial Builder to define the perturbation magnitude parameter for a gradual adaptation paradigm:

  1. Phases:
    • Baseline
    • Early Adaptation
    • Adaptation Plateau
    • Washout
  2. Trial Types:
    • no perturbation (assigned to: Baseline, Washout)
    • gradually increasing (assigned to: Early Adaptation)
    • full perturbation (assigned to: Adaptation Plateau)
  3. Sequence Types:
    • no perturbation = constant value
    • gradually increasing = gradual ramp
    • full perturbation = constant value
  4. Input Values:
    • no perturbation: Constant Value = 0%
    • gradually increasing: Starting Value = 0%, Ending Value = 100%
    • full perturbation: Constant Value = 100%
2. Left Panel  

Left Panel: Experiment Phases

The left panel is where you organize the experiment into phases. It consists of a list of “phases”, where each row in the list represents one “phase”. Each “phase” (each row) has the following elements:

Trial Type Dropdown

Each row has a dropdown menu to select the “trial type” for that phase. By default, you see three options: Baseline, Learning, and Washout. Select <add option> in the dropdown to create additional “trial types”.
Multiple rows (phases) can share the same trial type if needed. For example, you might have two separate phases that both use the “unperturbed” trial type but occur at different times in the experiment, such as pre and post learning.

Number of Trials

Next to the “trial type” dropdown, there is a numeric input field where you set the number of trials in that phase.

Adding, Removing, and Reordering Phases

You can use the + button at the top-right of the left panel to add a new phase row. Each row also has a delete button (trash icon) to remove it. You can click-and-drag a row to reorder phases, which changes the sequence in which they appear during the experiment.

Selecting a Phase and Viewing Parameters

Click on a phase row in the left panel to select it. This opens the “Trial Type Settings” panel (right panel) for the “trial type” associated with that phase. Note that there is only one “Trial Type Settings” panel for each “trial type”: if two phases share the same trial type, they both link to the same “Trial Type Settings” panel, and any changes will apply to all phases using that trial type.

3. Right Panel: Overview  

Right Panel: Trial Type Settings

The Trial Type Settings Panel (right panel) is where you configure the parameter values for each “trial type” selected in the left panel. You only need to configure a “trial type” once, and any phases using that “trial type” will automatically use the same settings.

The top row of the panel shows the name of the selected “trial type”, and the Sequence Type Dropdown (top-right) – which allows you to choose how parameters will change across trials (details below). The main area of the panel consists of a “parameter input” list, containing repeated instances of the “selected parameter group” (each row is one instance; note that it is possible that you may only have a single item in the list).

Defining trial-by-trial parameter values for the current “trial type” involves two steps:

  1. Select the correct sequence type using the “Sequence Type Dropdown”. This section will modify certain aspects of the “parameter input” list.
  2. Fill in the values for each row of the “parameter input” list, in a way that is appropriate to the selected sequence type. You may need to add / remove / reorder rows as needed.
4. Right Panel: Sequence Type  

Sequence Type Dropdown (Right Panel)

Each Phase Panel features a “Sequence Type” dropdown in its title bar (top right). Use this dropdown to select how parameters will vary across trials in this phase. Each dropdown option offers a different method for generating the trial-by-trial sequence of parameter values:

Deterministic options (predefined values and order, no randomness)

Constant values

Parameter values are constant across all trials in this phase. The right panel shows a single row of input fields where you can enter the fixed value for each parameter.

Gradual ramp

Parameter values change linearly trial-by-trial starting at the start value and ending at the end value you provide. The right panel shows two rows of input fields: one for the start value and one for the end value of each parameter.

Ordered sequence

Parameter values change trial-by-trial according to a predefined list of values, which you define using the right panel. The right panel shows multiple rows of input fields: each row corresponds to a single trial where you can enter the parameter values for that trial. These values are applied sequentially, trial-by-trial, in the order you set. Click “Add Value” at the top-right of the panel to insert new rows. Click-and-drag existing rows to reorder them, or click “Remove” on a row to delete it.

Randomized order options (random sampling of predefined values)

Random sequence

For each trial, parameter values are drawn with replacement from a list of values that you define using the right panel. The right panel shows multiple rows of input fields: each row represents one potential set of parameter values for one trial. Enter each potential set of parameter values on a separate row. Click “Add Value” at the top-right of the panel to insert new rows. Click-and-drag existing rows to reorder them, or click “Remove” on a row to delete it. The order of entries in the list is irrelevant. On each trial, parameter values are selected at random from your list using probability weights specified to the right of each row. Each weight is 1/1 by default (equal probability); weights are normalized automatically. Values are drawn with replacement, meaning that the same value may appear multiple times before others are used.

Blocked random sequence

For each trial, parameter values are drawn without replacement (with block reset) from a list of values that you define using the right panel. The right panel shows multiple rows of input fields: each row represents one potential set of parameter values for one trial. Enter each potential set of parameter values on a separate row. Click “Add Value” at the top-right of the panel to insert new rows. Click-and-drag existing rows to reorder them, or click “Remove” on a row to delete it. The order of entries in the list is irrelevant. On each trial, parameter values are selected at random from your list using equal probability across parameter values that have not yet been drawn. Values are drawn without replacement within each block (block = full list of values): every potential set of parameter values is selected exactly once before any repeats occur; when all values have been used, the block resets (list reshuffles).

Random values options (values generated from a probability distribution)

Uniform Distribution

Parameter values are randomly generated for each trial based on a uniform distribution. You define the minimum and maximum bounds, and all values within this range have equal probability. The right panel shows two rows of input fields corresponding to these bounds.

Normal Distribution

Parameter values are randomly generated for each trial based on a normal distribution. You define the mean and variance of the distribution. The right panel shows two rows of input fields corresponding to these parameters.

5. Implementation Example  
Expanded Example: Gain Visuomotor Adaptation Paradigm

In this example, we are working with a gain visuomotor adaptation paradigm using the parameter gainY to control visual perturbation. Here, the visual perturbation slows the appearance of the right hand:

  • gain = 1: No perturbation (the hand moves normally).
  • gain > 1: The hand appears slower than normal.

Our experimental design includes:

  • 20 Baseline (BL) Trials without perturbation
  • 100 Trials with gradual introduction of perturbation
  • 50 Trials at maximum perturbation value (gain = 1.5)
  • 40 Washout Trials returning to no perturbation

We can structure the experiment as follows:

  1. Phases (Left Panel):
    • Baseline (20 trials; Trial Type: No Perturbation)
    • Initial Adaptation (100 trials; Trial Type: Gradually Increasing)
    • Adaptation Plateau (50 trials; Trial Type: Full Perturbation)
    • Washout (40 trials; Trial Type: No Perturbation)
  2. Trial Types (Left Panel):
    • No Perturbation: Used in the Baseline and Washout phases.
    • Gradually Increasing: Used in the Initial Adaptation phase.
    • Full Perturbation: Used in the Adaptation Plateau phase.
  3. Sequence Type (Right Panel):
    • No Perturbation: Set as Constant (same value across trials).
    • Gradually Increasing: Set as Ramp (linear change from start to end value).
    • Full Perturbation: Set as Constant (fixed maximum perturbation value).
  4. Values (Right Panel):
    • No Perturbation: Constant value of 1.
    • Gradually Increasing: Ramp from 1 (start) to 1.5 (end).
    • Full Perturbation: Constant value of 1.5.
